# Local Omarchy audio plugin and UoW worker

Date: 2026-11-05
Status: approved for implementation; Omarchy is the sole sender

## Intent

The user wants an unpublished Omarchy bar plugin that automatically streams audio played through the laptop's current default output to the ESP32 Adaptive Engine at `192.168.254.75`. The bar should show whether capture and the receiver are responding and provide a visible off switch. UoW should record bounded authority decisions, effects, and observations so this device path can later be used safely by agents.

## What exists and what the test proved

- An installed Python CLI, desktop entry, and disabled user service already exist. The CLI currently starts `parec` without a device argument. Omarchy's default source is the microphone, so this command does not select laptop playback. Its telemetry parser uses offsets 36/40 for crossover frequencies, while the checked-in ESP32 packet layout uses 44/48. A synthetic packet confirmed the displayed values are wrong. The CLI also contains a dashboard access token in a world-readable file. These files will be left untouched during initial development.
- The Omarchy speaker monitor was captured explicitly during a bounded 997 Hz tone. The laptop sent 48 kHz, stereo, signed 16-bit PCM in 256-frame `UDPA` packets. The ESP32 returned valid 184-byte `RCTM` packets after a firewall rule limited to that ESP32 was added. The tone's physical output is still unverified; firmware does not populate `ref_rms` in network telemetry.
- UoW-v3's local gateway currently supports only `observation.ingest` and `observation.summarize`. It has durable receipts and deny-by-default policy but no OS-enforced separation from other programs running as `nb11b`.

## Approaches considered

1. **Omarchy bar plugin plus separate UoW audio worker — selected.** QML provides status and controls; a separate process owns capture, UDP transport, telemetry validation, and UoW requests. The stream continues when the panel closes but stops when the plugin is disabled or removed. This preserves a small, responsive shell plugin and a testable worker.
2. Native C++/Qt Omarchy app. It provides a full window and package lifecycle but adds a second interface for a task that fits the existing bar. A separate authority worker would still be needed.
3. Extend the installed Python launcher directly. It has a familiar command but currently selects the wrong source, misreads telemetry, exposes a dashboard token, and can be invoked outside UoW. Replacing it now would blur qualification of the new path.

## Scope and behavior

- Plugin ID: `nb11b.adaptive-audio`, local only. It is a `bar-widget` with `BarWidget.qml` as its sole manifest entry point and a nested `Panel.qml`. No GitHub publication or Omarchy package is part of this milestone. Source lives in the UoW workspace; installation copies validated files to the user-owned plugin directory. The built-in `omarchy.audio` widget remains available.
- At login, the enabled bar widget starts the worker if the saved preference is enabled. Initial installation sets that preference to enabled, as requested. Turning it off in the panel persists across logins. The widget owns the worker lifecycle and sends a short heartbeat; if the widget is disabled, removed, or the shell exits, the worker stops capture within 3 seconds. Closing only the details panel leaves streaming active. A prominent icon distinguishes streaming, waiting for ESP32, paused, and error. The panel shows the selected output, target, rolling packet rate, last valid telemetry age, reported crossover frequencies, and receiver underrun/drop counters. It never displays an unpopulated `ref_rms` as proof of sound.
- The worker follows the **current default output**. It resolves that sink's `.monitor` and passes it explicitly to `parec`; it never falls back to a microphone. On a default-output change, it closes the old capture and reopens the new monitor. Apps deliberately routed to another output at the same time are outside this version.
- Audio format and target are fixed in the first policy: `192.168.254.75:4000`, 48 kHz, stereo, signed 16-bit little-endian PCM, 256 frames per packet. The worker uses the repository's packed 22-byte `UDPA` header. The target address and ports are not editable from QML. No audio is saved to disk.
- Before capturing playback, the worker sends bounded silent packets and requires fresh, well-formed `RCTM` telemetry from `192.168.254.75:4002` (184 bytes, magic, version, declared size, increasing sequence within a receiver epoch). After a disconnect or board reboot, a new silent preflight establishes a new sequence baseline. If no telemetry arrives or it becomes stale for more than 3 seconds, the worker stops playback capture and retries silent discovery with backoff. Status says *receiver responding*, never *audio heard*. It must not treat another host's UDP packet as confirmation.
- The worker is the only local owner of UDP 4002 and uses a process lock so another local instance cannot run. **Approved deployment decision:** Omarchy is the sole audio sender; the Windows streamer is stopped before this worker is enabled. The ESP32 protocol does not authenticate or identify a sender, so two simultaneous senders would interfere. Supporting both laptops would require board-side session ownership in a later design.
- The panel has on/off control. Stop always terminates capture and UDP transmission promptly, even if UoW is temporarily unavailable. Start fails closed when the UoW gateway or policy is unavailable. A worker crash never resumes streaming without a fresh receiver preflight and policy decision. Disabling/removing the plugin stops the worker; an uninstall command also removes its user files after stopping it. There is no independent audio user service that could stream invisibly after the widget is disabled.
- Crossover values are read from verified telemetry at offsets 44/48. A `audio.dsp.crossover.set` capability is designed but disabled in the initial live policy until hardware-safe low/high envelopes are supplied. When enabled, it must validate both ranges and `low < high`, record an intent, send a bounded number of UDP control datagrams, and require matching fresh telemetry before reporting *applied*. A datagram alone is only *sent*.

## UoW boundary

- Extend the existing service with typed `audio.stream.start`, `audio.stream.stop`, and `audio.dsp.crossover.set` intent transitions. Empty policy denies all three. The fixed destination, monitor-only source, format, and startup preference are server-side constraints. Each accepted request gets a durable intent receipt before any device effect.
- The worker reports a separate effect outcome through a service-only operation: started with fresh receiver telemetry, stopped, failed preflight, telemetry lost, or interrupted/recovered. The UoW journal holds an intent and a later outcome; recovery replays the ledger but never re-executes an old effect. Request IDs and session IDs make retries idempotent. On restart, an intent with no outcome becomes *uncertain* until the worker reconciles the local process and receiver; it is never converted to success merely from the old receipt.
- Telemetry is ingested as a typed audio observation through the Observation Harness, with bounded units for packet rate, counters, telemetry age, and reported frequencies. It is marked `UNVERIFIED_CLAIM`: source IP and packet shape do not authenticate firmware. The existing environmental temperature/percent profile remains strict.
- The plugin has no UoW token, dashboard token, or raw audio access. It calls a fixed local status/control interface with bounded JSON. Dynamic text is plain text in QML, and no untrusted value is interpolated into a shell command. The worker owns the UoW credential in a mode-0600 file. A user-level UoW gateway starts before the widget worker; if the gateway is unavailable, the worker retries without sending playback. Under the current same-user setup this is an audited operator-approved automation, not an OS security boundary or independently governed agent capability. Agents are denied start/control access until a separate restricted service identity and bypass test are approved.

## Recovery and acceptance

- Worker state is written atomically. Start after login rechecks policy, current default sink, UDP port ownership, and ESP32 telemetry. A saved *paused* preference stays paused. A crash or stale telemetry stops capture; restart records an interruption outcome and performs a new silent preflight. The old installed streamer remains disabled during qualification. The plugin's status heartbeat prevents a disabled widget from leaving a hidden stream running.
- Tests cover default denial, missing/invalid token, destination and source substitution, malformed/nonfinite crossover values, reversed crossover order, duplicate requests, stale/spoofed/truncated telemetry, sink switching, rate measurement over a steady window, stop during loss of gateway, worker restart, and UoW receipt replay. Local fake PipeWire/UDP inputs are used for automated tests; no personal playback is recorded.
- Host qualification checks `omarchy plugin validate`, `/usr/lib/qt6/bin/qmllint`, plugin open/close, disable/removal and off toggle, login autostart, explicit monitor capture, rolling packet rate during a steady stream against the 187.5 packets/s theoretical rate, valid ESP32 telemetry, and recovery after Wi-Fi/ESP32 loss. A quiet generated tone confirms nonzero laptop capture. Counters sampled after stopping are not used as steady-stream evidence. Physical audio output and long-duration stability remain separate gates requiring device serial or output measurement.

## Installation boundary

After the implementation and tests are reviewable, the user-owned plugin files, worker executable, and UoW gateway service can be installed locally. Installation must back up or refuse conflicts, avoid changing stock Omarchy files or system privileges, and leave the current Python streamer intact until the new path is qualified. The dashboard token embedded in that legacy launcher requires separate rotation/removal before the launcher is used as a trusted control surface.
